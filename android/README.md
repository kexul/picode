# 手机提醒 app（android/）

一个自己装的小安卓 app：电脑上跑着 pi-chat 的后端（pichat），它连着后端的提醒流，
「跑完一轮」「等你答题」时在手机上弹一条 Android 的通知；点通知在 app 里直接看那个会话（装的就是后端给的那份界面，跟浏览器页面同一份）。
不用任何第三方推送服务——app 跟后端连的是同一条局域网。

## 后端要改什么

不用改。后端从 2026-11 起（本次改动）自带 `GET /phone-notice` 这条 SSE 推送口：
app 连上去就挂着，弹桌面卡片的同时会往这条流里推一条（`type: notice`），
有人回话、会话关掉、题答完时推一条（`type: close`）把手机那条通知撤下来。
桌面卡片关掉（设置里的 notifyTurnEnd）时这条流也不推。

另外它还有 `GET /media-manifest.json`：界面文件（`media/` 里那几份 js / css）此刻的指纹，
一份「文件名 → 指纹」的清单。app 拿它跟包里带的那份比，看包里的界面旧没旧（见下面
「包里这份界面是不是旧的」）。后端没有这一条也不要紧：app 只多一行「没查成」，其它照旧。

还有「打包并安装新版」那三条（见 `src/apkBuild.ts`）：`POST /apk/build` 叫电脑现打一次包、
`GET /apk/build` 问进度、`GET /apk` 把包发过来。这三条只有后端本身在仓库源码里跑时才做事
（它得手边有 `android/` 源码、Android SDK、JDK）；装的是插件包的电脑上会回一句「编不了」。

## 装 app

1. 编 APK（本机就编，要 Android SDK + JDK 17，仓库外不用装别的）：

   ```bash
   cd android
   # 用一份独立的 Gradle 用户目录编：全局 ~/.gradle/gradle.properties 里配了本机代理，
   # 代理没在跑时下载会卡死，别让这个项目跟着走那份配置
   GRADLE_USER_HOME=$PWD/.gradle-home gradle assembleDebug
   ```

   （依赖走阿里云镜像，见 settings.gradle；`gradle` 没在 PATH 里就用
   `~/.gradle/wrapper/dists/gradle-8.14-all/*/gradle-8.14/bin/gradle` 那支。）

   也可以直接跑仓库根目录的 `build.bat`：它除了插件、exe，顺手把这个 APK 也打一份
   （没装 Android SDK 的机器上会跳过这一步，不影响其它产物）。

   编出来的是 `app/build/outputs/apk/debug/app-debug.apk`，传到手机装上。
   懒得传文件就在仓库根目录跑 `npm run apk`：它会自己找到编出来的 APK，打印一条手机能开的地址，
   手机上打开那一页点一下就能下（下完 Ctrl+C 关掉）。

   装过一次以后就不必这么麻烦了：设置画面里选中那台电脑、它右边冒出那颗向下的箭头，
   点一下就让电脑现打一个、手机自己下下来弹安装（见下面「用的时候要知道的」）。
2. 手机上打开 app，第一次就在那一行里填后端地址（浏览器里打开的那个，比如 `192.168.1.40:1867`），
   点「打开」（或者键盘上那颗「前往」）。以后这一屏就是一张连过的电脑清单：点一行选中、
   点底下那颗「打开」进去；再连一台新的，点清单底下的「＋ 另一台电脑」。
3. 通知栏那条常驻提示变成「已连接」就是通了。

打包的时候，仓库根目录 `media/` 里那几份界面文件（`chat.js`、`chat.css`、画图的 `pele.js`
和 highlight / marked 这些）会由 `app/build.gradle` 里的 `bundleMedia` 任务拷进 APK 的 assets，
并给每份算一个内容指纹。手机上打开对话时，app 拦下 `/media/xxx?v=指纹` 这类请求：
包里那份的指纹跟地址上的对得上，就直接从包里读（第一次打开不用从电脑上下那 600 KB）；
对不上（插件升级过了、包是旧的）就照旧走网络拿新的 —— 所以手机上永远不会看到跟电脑不一样的旧界面。

改了 `media/` 里的东西以后重打一次 APK 就跟着更新；不重打也不会错，只是那一次照旧走网络、慢一点。
包里的界面旧没旧，在设置画面那张清单里、选中那台的右边就能看到（见下）。

## 用的时候要知道的

- **设置画面怎么用**：一张「连到哪台电脑」的清单，一台一行。
  - 点一行 = 选中它（左边那个点实心），顺手就问一句这台后端的界面文件旧没旧；
    要进去得再点底下那颗「打开」。已经选中的那行再点一下，就是重新查一次。
  - 长按一行 = 把它从清单里删掉（删的只是记下的地址，已经连着的不断）；
    清单按最近连过的排，最新的在最上面，最多留 8 台。
  - 清单底下「＋ 另一台电脑」：展开填地址那一行，填完点「打开」或者按键盘那颗「前往」；
    一台都还没连过的时候，这一行直接就在。
- **选中那台右边那几个记号**：
  - 「查…」：正在问那台后端（几 KB 的一个请求，五秒没答就算没查成）。
  - 绿勾：包里带的那几份 js / css 就是这台电脑上现在用的那几份。
  - 橙色的向下箭头：包里带的那几份 js / css 跟这台电脑上现在用的对不上（电脑上已经改过了），
    点它就现打一个包装上（见下面）。在那之前照旧走网络拿新的，界面不会错。
  - 「没查成」：连不上那台后端，或者电脑上那份界面清单取不到。

  它只比界面文件。app 自己的改动（通知怎么弹、返回键几下回设置这些）不在这份清单里，
  那种得看仓库里改没改，改了就重新打包装上（`npm run apk` 或者 `build.bat`）。
- **那颗向下的箭头（打包并安装新版）**：点一下，电脑上现跑一次 gradle 打包（跟 `build.bat`
  里那一步同一条命令），打好后 app 自己下下来、弹系统的安装确认框，点「安装」就换上新版。
  几点得知道：
  - 得是**从仓库源码起的后端**（`npm run server`、或者在源码里 F5 起的插件）才有得打；
    装的是插件包 / 那个 exe 的电脑上手边没有 `android/`，只会回一句「这台电脑上编不了」。
  - 电脑上要有 Android SDK + JDK 17，还要能找到 gradle（PATH 里，或者 `~/.gradle/wrapper/dists` 里）。
  - 第一次装之前得在系统里允许这个 app「安装未知应用」（app 会自己带你去那一步）。
  - 每次打出来的版本号都会抬高一点（按时间戳），所以系统认得出是升级；装的时候 app 会重启一下，
    填过的地址这些照旧留着。
  - 打包那一阵横条是转圈（只有“还在跑”和跑了多少秒，给不出百分比）；下载那段按字节数长，
    断了不从头来：停一两秒后从已下到的那个字节接着要（后端认 Range，最多试 5 次），
    包还是边下边写进安装器、不落磁盘。
- **手机要跟电脑在同一个网络里**。出门在外收不到（后端只在内网里听着）。
- **通知不出声 / 不弹横幅**：先看通知栏常驻那条是不是「已连接」；是的话多半是系统把这个 app
  的通知归了静默，或者电池优化把它冻了——到系统设置里关掉这个 app 的电池优化（各品牌入口不一）。
- **点通知**：进 app 里那个会话（WebView 装着的就是后端给的那份界面，跟浏览器页面同一份）。
  页面本来就开着的时候不整页重来（那样会闪一下、会话列表和滚动位置都重来）：只在页面里切一格，
  就是顶条上点一格那一下（`window.pichatSwitchSession`，见 MainActivity 的 openPage）；
  页面没开过、或者刚改过地址才整个加载一遍。
- **回设置要按两下**：看对话时连按两下系统的返回键（或返回手势，两下间隔不超过两秒）才回设置画面，
  只按一下会弹一句「再按一次回设置」、什么都不动——手一滑就离开对话太容易了（回设置时网页会被清掉，再打开等于重开）。
- **换了后端端口 / 地址**：点「＋ 另一台电脑」，填新的地址即可，不用重装。

## 为什么这么做（跟别的路子比）

- 不用 FCM / 厂商推送：那些要么在国内手机上不可用，要么接入繁琐；同一局域网里自己连最简单。
- 不用浏览器 Web Push：那条路要 service worker + VAPID 密钥，iOS 还得先加到主屏幕；app 这条最省心。
- 提醒流跟桌面卡片是同一套触发点（chatHost 的 trayNote / closeNotice），不会一边弹一边不弹。
