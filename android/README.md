# Pi Chat 提醒（安卓 app）

手机上收「会话跑完一轮 / 模型在等你答一句」的通知。

界面是原生的，两屏：

- **会话列表**：按哪台机器分组，组头写那台的名字（本机那组写「本机」，别的机器上的写那台的名字，如「家里」——就是它设置里那项「这台叫什么」）。跟另一台配对（设置面板「配对」里填它的地址、两边都点头）之后，
  它现在开着的会话就都列出来；没配对的机器一律不列。
  组内一行一个会话（会话名、最后一条的一两句、时间；最近一道题还没答的写一行「在等你答一句」），
  名字里不再带「家里 · 」那种前缀。
  有事的排前面：组内按最后一条的时间倒着排，组与组之间最近有事的那个组排前面。
  左边那颗状态点跟网页端一个规矩：**正在跑是蓝点、一明一暗地呼吸**
  （正在跑包括「后台还有命令没跑完」），**闲着是绿点、不闪**。
- **会话页**：点一行进去，一条条看这个会话里的事（跑完说的话、模型问的题、自己说的那句），
  底下能回一句；问的题底下有选项，点一下就答。**正在跑的时候最底下多一张「这一轮」卡片**：
  就是这一轮已经写出来的原文（每 4 秒自己刷一次，跟着长），跑完就收起来
  （那一轮的原话会作为一条「有事」推过来）。所以点开一个会话，上一轮最后说了什么总能看到。
  跟着新的往下走，只限人贴着底的时候：往上翻着看旧消息时，新内容来了也不拽你，
  等你自己滑回最底下才继续跟。
  别的机器推来的会话也能回：
  这台把这话转给原来那台，那边当成你说的一句。
  正文按 markdown 画：段落、标题、列表（项首对齐）、表格（`TableLayout`，表头灰底、按分隔行左/中/右对齐、
  列多了横着滑）、引用、代码块（能选、能横向滑），行内的粗体 / 斜体 / 删除线 / 行内代码 / 链接文字。
  **解析不在手机上**：后端推过来的每条通知都带着一份「怎么画」的结构（`src/markdownBlocks.ts`），
  `Markdown.java` 只照着画 —— 桌面那个小窗口收到的也是同一份，两边画得一样。
  跟网页端一个规矩（单个换行就是换行）；只做聊天里常用的那几样：脚注、HTML、图片、嵌套列表这些不认。
  列表上那一行是去掉记号的一句话。

顶上只有一颗「设置」：点它摊开填后端地址那一块，底下写着现在连到哪儿了（「已连上 / 重连中…」）。
地址还没填时它自己摊开，那时也收不起来。列表空的时候中间有一句人话和一颗「重新连」；
连不上后端（地址写错、后端没开）时也会把填地址那块摊开。

## 怎么用

1. 装上去，打开，填后端地址 —— 就是你在浏览器里打开 Pi Chat 时那个地址，例如
   `http://100.73.225.24:51883`（只写 `100.73.225.24:51883` 也行，会补上 `http://`）。
2. 点「保存」。那行收起来，列表出来，通知栏里出现一条常驻的「Pi Chat」。
3. 之后某台后端里跑完一轮、或者模型在等你答一句，手机就弹一条：标题是会话名（别的机器推来的前面带那台的名字），
   底下是回复开头；点它直接进那个会话页。
4. 在会话页里正看着这个会话时不再弹通知；自己刚说的那句也不弹。

- 通知栏里那条常驻的（写着「已连上 / 重连中…」）别关掉也别嫌它碍事：它就是那个前台服务，关掉系统很快就会把后台连接掐了，
  通知就收不到了。app 里没有关它的开关：地址填了就一直挂着（想改地址、看连接状态，点它一下）。
- 这一路跟着后端设置里那颗「弹窗通知」走：那儿关掉，手机上也不再弹。

## 安卓上要做的几件事

- **允许通知**（Android 13 起第一次打开会问；问过以后在系统设置 → 应用 → Pi Chat 提醒 → 通知里改）。
- **允许自启动 / 后台运行白名单**（小米的「自启动」、华为的「应用启动管理」、OPPO/vivo 的「允许后台运行」这类）。
  不做的话，系统把 app 杀掉以后就收不到，得自己再打开一次。
- **电池优化设成「不限制」**（同一个应用详情页里），不然连着连着会被冻住。
- 锁屏上要看得见、要响，就在通知设置里把「会话提醒」这颗通道设成「响铃 + 悬浮/锁屏显示」。

## 怎么工作

- 前端服务（那颗常驻通知）挂着一条到后端的连接：`GET /phone?client=<这台手机的标识>`。
  连上先收一份现状（开着哪些会话、每个会话留着的那几条），之后有新的一条推一条；25 秒一次心跳。
  断了自动重连（刚断 2 秒后就试，一直连不上一路退到最多一分钟一次）。
  后端明说「停了」（`end`）也照旧过一会儿再试（那边很快就回来的时候多，不让人去点）；
  列表上那颗「重新连」是不想等时自己催一下。
- 收到的东西都放在内存里（`Store`）：列表和会话页都照着它画，会话页里来了新的一条就实时加进去。
  整个进程被系统收掉了就重新连一次，后端连上时会先给一份现状。
- 进会话页时还会拉一次 `GET /phone/session?id=…` 对齐（长连接上漏掉的、别处答过的，这一下补齐）。
- 回一句走 `POST /phone/send`（别的机器推来的会话，后端自己转给那台）；答一道题走 `POST /phone/answer`（带 `cardId`、选项原文、自己写的那句）。
  没成的把后端给的原因用 Toast 说出来。
- 一道题在别处（网页上、另一台设备上）答掉了：后端推一条 `askdone`，这边把那几个选项置灰。
  断线重连后也会从那份现状里知道哪些题答过了。
- 没有口令：跟 `/notify` 一个规矩，机器对机器、不带 Origin —— 只在信得过的网络里用（同一个局域网、
  自己的 tailnet，或者前面挂的 https 反代）。

## 怎么编、怎么装

仓库里这份不引任何第三方库（纯 Android SDK：原生控件 + `HttpURLConnection` + 系统通知）。

```bash
cd android
./gradlew assembleDebug                       # 或者 Android Studio 直接打开这个目录
# 产物：app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

仓库根目录的 `build.bat` 也会顺手编它（不想要就加 `skip-android`；没找到 SDK 或 javac 时会跳过并说一句）。

- 要 JDK 17 以上、Android SDK（`compileSdk 36`）。没有 `./gradlew` 就用本机的 Gradle 8.13 以上直接跑：
  `gradle assembleDebug`。
- `local.properties`（`sdk.dir=...`）是这台机器的路径，不进版本库。
- 用 debug 签名就够：自己手机上装，不往上架。
