# 领域文档

写代码的技能在摸这个仓库之前，按什么规矩读这里的领域文档。

## 摸代码之前先读

- 根目录的 **`GLOSSARY.md`**，或者
- 根目录的 **`GLOSSARY-MAP.md`**（如果有）：它指向每个上下文自己的 `GLOSSARY.md`，
  把跟这次要碰的话题相关的都读一遍。
- **`docs/adr/`**：读跟你要动的地方有关的 ADR。

这几个文件不存在就**当没这回事，接着干活**：不用提它们不存在，也不用劝人先把它们建起来。
`/domain-modeling` 技能（`/grill-with-docs` 和 `/improve-codebase-architecture` 会走到它）
会在真的定下词、真的定了决定的时候顺手建。

## 文件怎么摆

本仓库是单上下文：仓库根一个 `GLOSSARY.md`，加一个 `docs/adr/`。

    /
    ├── GLOSSARY.md
    ├── docs/adr/
    │   ├── 0001-xxx.md
    │   └── 0002-yyy.md
    └── src/

## 说话用词表里的词

产出里提到某个概念时（issue 标题、重构建议、猜想、测试名），用 `GLOSSARY.md` 里定的那个叫法，
别漂到它明确说不用的同义词上去。

想要的概念词表里没有，是个信号：要么你在发明这个项目不用的说法（那就再想想），
要么真缺一个词（记下来给 `/domain-modeling`）。
